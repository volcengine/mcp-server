# 短信 MCP Apps

七种表单由同一个自包含 HTML 资源承载。使用官方 MCP Apps SDK 的 AppBridge 调用本服务工具，不依赖 localhost HTTP 或浏览器存储。文件使用服务端下发的单文件能力直传 ImageX/TOS，账号 AK/SK 不进入页面。

`src/styles/{qualification,signature,traffic,batch,service}.css` 原样复制自 byted-sms-sender 1.4.6 对应的 `*_wizard.css`（参考仓库提交 e3d7e1f997671590cb1c26d1977f0dcd19abcba2）。布局和组件沿用 React 18.2.0、Arco 2.66.15；窄屏、对话卡片和主题覆盖在 `host.css` 中维护。这里的构建和运行都不读取或修改 Skill。

图片附件支持本地缩略图和点击放大，保留原上传控件、表单布局和业务调用。选中图片后预览本地 File，上传成功后在页面保留 Blob；预填 Base64 图片直接预览。替换、移除或页面卸载会释放 Blob URL，切回步骤时可从页面内的 Blob 恢复预览。只有远端文件引用时仍显示文件名，不额外查询 ImageX/TOS。预览数据不会进入业务提交或模型摘要。

材料上传按 ImageX [固定上传入口](https://www.volcengine.com/docs/508/1537728)协议执行：`PUT /<StoreUri>`，携带 `Authorization`、`Content-CRC32` 和 `Specified-Content-Type`，响应 `success: 0` 后再提交上传确认。`form_config.json` 的 `materialUpload.uploadHosts` 首项是实际入口（全球加速），区域入口保留供配置切换；服务端、前端和 CSP 共用该配置。ImageX 返回的动态 `UploadHosts` 不再作为上传目标，也不再逐一匹配历史域名。没有自动换域名重试。升级后应重新打开已有表单，加载对应上传协议的新版页面。

前端开发使用 Node.js 22.12 或以上版本；部署预构建的 Python wheel 不需要 Node.js。

```bash
npm ci
npm test
npm run build
```

构建输出 `../src/mcp_server_sms/static/forms.html`，由 Python 包随 wheel 分发。业务数据不能写入 HTML。修改前端后需重新构建再打 Python 包。

`npm run dev` 后打开 `/dev/preview.html` 可预览六个表单、窄屏和深色模式，内嵌高度随 AppBridge 通知自动调整。可用 `?form=service&scenario=renewal&theme=dark&width=narrow` 直接打开指定预览；省略参数使用默认值。这里使用官方 AppBridge 与跨源双 iframe 沙箱及模拟业务数据。`dev/sandbox.ts` 复用官方 ext-apps 的 basic-host 沙箱。生产构建不包含这些预览代码。构建器生成的 `THIRD_PARTY_LICENSES.md` 随 Python 包分发。

上传使用 `prepare_*` → 存储 HTTPS 直传 → `complete_*`。CSV 直传后自动核对任务，调用 `complete_recipients_upload` 一次回读共同完成校验与可选引流检查；相同输入的完整结果可在当前页面复用。`uploads.test.jsx` 使用严格的 32,000 字符宿主模拟与合成大文件回归；真实豆包的 CSP、CORS、上传授权与接口权限需另做联调。文件上传失败允许重选，正式提交结果未知仍锁定。

模型可见工具主要查询资源或打开页面；资质、签名、引流、模板和群发写入仍由页面使用 App-only 工具执行。单条短信不提供表单，模型在对话中补齐并确认消息组、签名、模板、一个收件号码和变量后调用模型可见的 `send_sms`；多个号码、定时发送和逐号码变量统一使用群发页面。`open_batch_task_form` 的 `prefill` 用于新建，`task` 用于查看和管理已有任务；两者互斥。

模板核对调用 App-only 的 `preview_template`：先校验原生字段，再查询 `ListAllSmsProduct`，小微账号的通知变量、未开放的营销变量会阻断申请；显式引流 ID 在当前账号下回查并补齐原始绑定内容，随后用原始正文与布尔 `useVolcLink` 调用 `CheckTrafficDrivingExist`。固定资源缺失、查询失败或结果不完整都不能进入确认。固定项和变量合计最多一个链接、两个号码和一个 Path；验证码仅允许一个普通变量、指定用途词且不含引流。通知与营销模板最多包含 20 个变量且不允许相邻占位符；营销模板正文必须以“拒收请回复R”结尾。名称按 UTF-16 最多 50 字符、UTF-8 最多 100 字节，用途最多 300 字符；保留变量名会阻断核对。

核对页保留固定引流状态和参考流程的风险提示。`submit_template` 必须携带本次 `confirmation`，提交前重复只读检查，参数、账号身份或引流事实变化后重新核对；校验及预览不触发申请。确认信息与补齐后的参数仅通过页面私密结果返回，AK/SK 不进入页面。已知失败保留填写内容并撤销确认，未知写入锁定重试；摘要只报告模板 ID 与状态。模板创建表单以 `vconsole-sms-v2/src/components/SmsTemplateComponents` 和 `SmsTemplateParamsComponents` 为 UI 基准：基础字段使用 Arco 垂直表单的 14px 常规字重 label、8px 标签间距和 20px 表单项间距，412px 两列排布在 852px 内容宽度内；变量及引流使用表格分区和 40px 区块间距。引流信息主表仅展示变量模版内容、各变量绑定值及删除操作；“添加引流信息”通过弹窗从当前账号的链接库或号码库选择，不把资源选择与原始值输入同时摊在主表。

模板页不提供项目、适用消息组、不限定消息组、手动提取变量或变量名称输入控件；项目和消息组仅保留宿主已有预填值，未预填范围时省略接口字段，不额外查询或要求选择消息组。正文完整占位符自动生成去重的变量类型选择，保留同名变量的原生配置和绑定，新变量按主项目前端默认选择普通变量。切换验证码模板会强制所有变量为普通变量并清除引流绑定；验证码仅可选择普通变量，通知与营销创建页不提供超级变量。输入尚未完整时保留已选类型且不打断填写，核对时仍严格校验正文与变量类型。

模板名称、类型、签名、用途、正文、变量设置、短链和引流绑定等本地校验错误使用字段错误态与控件下方帮助文案展示；核对时自动滚动并聚焦首个错误项。账号前检、固定引流检查和上游接口失败等无法归属单个输入项的错误继续使用页面顶部反馈。

变量引流只能选择当前账号引流信息库中的资源 ID：链接列表调用 `GetTobTrafficDrivingLinkListForAgent` 并按平台短链开关传递 `useVolcLink`，号码列表调用 `GetTobTrafficDrivingPhoneListForAgent`；切换平台短链模式会清空旧组合并重新加载对应链接库。预览和提交都会按 ID 回查当前账号资源并补齐原始内容，同时使用 `CheckTrafficDrivingExist` 检查正文固定引流。写接口按契约提交 `templateTrafficDriving: [[{ name, paramType, id }]]` 和服务端检查得出的 `fixTrafficDriving: [{ paramType, id, content }]`。

签名表单的候选使用 `GetApplySignatureBind` 原生数组，空结果 `null` 表示没有候选；不依赖 `auditStatus/usable`，不分页或逐条补查。预填资质必须出现在该候选数组中。名称风险提示和提交确认在页面完成，提交时只调用 `ApplySmsSignatureV2`，不再次查询资质。

签名页面沿用 Skill 的“签名信息 → 资质材料”两步结构及 Arco `Select/Input/Upload/Modal` 组件。签名归属筛选可用资质；已预填的有效资质及归属锁定，唯一候选自动填入企业全称。发送类型固定 `CN_OTP/CN_NTC/CN_MKT`，公司、APP、商标的字段、材料格式和名称规则与 Skill 一致。所有材料分类合计最多五份，单文件沿用 MCP 的 10 MB 限制；预填材料需要上传后才能核对，当前来源以外的附件不进入申请。项目名称只保留预填值，不额外增加 Skill 没有的表单项。

核对申请后普通名称可“确认提交”；名称未连续出现在企业全称中时，必须通过“强制提交”的 Arco 确认弹窗接受风险。修改字段或材料会撤销预览，已知失败可重新核对，未知写结果锁定编辑和重试。放弃填写只清理当前页面草稿并报告结束。结果页沿用 `ListSignaturesForAgent` 刷新审核状态。`signature.test.jsx` 覆盖这些行为及原生参数、附件引用、批量上传和提交防重。

引流页面沿用 Skill 的 Arco `Select/Input/Alert/Button` 控件和录入、预览布局，布尔短链选择、协议、七种号码类型、个人证件及企业字段保持一致。自有链接支持选填跳转信息，火山短链只提交跳转分支；域名和 Path 自动解析并只读回显，完整链接保留原值和查询参数。预填号码推断类型，文案链接自动识别协议，号码格式和必填错误显示在字段旁。开表已指定 `kind` 时固定资源类型；未指定时可在页面选择链接或号码。

“预览录入内容”继续调用 `preview_traffic_resource` 校验格式、协议及重复项，通过后才显示“确认录入”。编辑、添加、移除或切换类型均撤销旧预览；已知提交失败需重新预览，未知写结果锁定编辑和重试。链接最多十条、号码最多一百条，提交仍使用 MCP 的两个 `BulkCreateTobTrafficDriving*ForAgent` 接口；按原生空字符串响应报告受理，不自动回查资源 ID。结束本次录入清除页面草稿并报告结束，私密字段只在页面及业务请求中使用，模型摘要只含类型和数量。`traffic.test.jsx` 覆盖原生字段、分支隔离、格式校验、预览撤销及失败处理。

MCP 宿主可能不允许原生表单提交，签名页的“下一步”和“核对申请”、引流页的“预览录入内容”直接通过按钮事件执行；普通输入框的 Enter 同样触发页面动作。交互不依赖 iframe 的 `allow-forms` 权限，回归测试同时覆盖宿主阻断原生 `submit` 时的按钮与 Enter 操作。

本地样式预览不进行文件上传，也不伪装成功；上传行为由 `uploads.test.jsx` 的合成大文件与模拟 HTTP 回归验证。真实宿主测试需单独授权。

群发创建页沿用 Skill 的任务信息、上传文件、发送时间、可选试发、校验结果与确认同页布局，使用 Arco `Form.Item/Upload/DatePicker/Radio/Descriptions/Checkbox`。输入项使用原生垂直 `Form.Item` 标签、8 px 标签间距和必填标记，不再复用引流页 `Field`；标签为 Arco 标准的 14 px 常规字重、次级文字色，整页字段说明标签保持相同视觉规则，深色模式使用 Arco 主题色。上传区按参考页先展示带下载图标的“点击下载模板”，再展示蓝色“点击上传文件”，下方为编号说明；开表配置启用的引流检查随名单校验执行，只在校验区展示结果，不增加勾选项。保留 MCP 的资源选择、CSV 列顺序和 10 MB 限制；选框仅在还有候选时展示“加载更多”，不展示加载统计。定时时间按北京时间显示至分钟，提交使用 Unix 秒并保留宿主预填的秒数；禁选过去日期和 30 天以外日期，边界日期同时限制时分，核对和最终提交均校验未来 30 天。恢复原页的默认 08:00–21:30 提示，日内限制与账号例外由服务端判定。上传完成且信息完整后延迟 300 ms 自动调用只读校验，特殊通知同时预检任务正文；失败后需修改输入或手动重新核对。统计分别展示总行数减重复行数所得的有效号码和重复数据，不把原始总行数误称为有效号码。修改信息、文件或发送时间撤销旧确认；完整名单结果可复用，部分引流检查保留覆盖率、原始错误和排障编号且不缓存。

完整预填的任务名称、消息组、签名、模板和必填任务正文核实通过后，“任务信息”按参考页使用 `Descriptions` 只读展示，说明为“以下信息由已确认的短信资源生成，仅支持查看。”；特殊通知展示实际任务正文并保留原始内容。空白、部分预填或资源失效时继续提供填写入口，说明明确要求填写和选择；补全后仍可编辑，不突然锁定。页头提示、文件就绪提示及操作图标沿用参考页，文件大小取上传回执；副标题、校验说明和确认按钮按 MCP 的创建、启动两次确认调整，避免把创建成功表述为已发送。

勾选同意后仅调用 `create_batch_task`；创建成功仍须在任务详情中另行确认启动。已知失败重试保留同一确认请求的幂等键并重新勾选，未知创建结果锁定编辑、重试和结束。结束预览只清理本页草稿并报告 `abandoned`，历史任务继续走独立的查询、启动、取消确认。试发的说明、手机号布局、变量名和占位提示、成功提示与“刷新发送结果”按钮沿用原页，维持 MCP 的单独确认与按 Message ID 回查。发送记录按返回的毫秒时间展示发送及回执时间、计费条数和原始错误；无记录提示稍后刷新，不自动重发。`batch.test.jsx` 与既有表单回归覆盖上述行为。`?form=batch&scenario=ready` 使用明确的模拟既有上传回执展示自动校验，`scenario=partial` 展示待补任务名称的填写入口，另有定时、引流部分失败、特殊通知和创建未知结果场景；这些场景均无真实账号或存储请求。

服务开通页沿用 Skill 的国内短信产品卡片、编号协议清单、Arco `Checkbox/Button/Spin/Result` 及首次开通、重新签署、取消和完成文案。协议、计费和控制台链接通过宿主 `openLink` 打开，无该能力时回显完整地址。首次打开仅调用 `get_sms_service_onboarding`，勾选后才向 `submit_sms_service_onboarding` 提交当前 `confirmation`；协议签署和商品开通由 MCP 执行。刷新撤销旧同意，已知失败必须刷新并重新勾选；已受理或未知写入不能被旧可提交状态解锁。取消只结束当前页面并报告 `abandoned`。结果页保留状态刷新、原始失败及排障编号，`service.test.jsx` 覆盖这些行为；预览支持协议更新、待生效、未知结果、欠费关闭及已开通场景。

普通发送和群发试发仅把用户确认的原生发送参数交给 MCP，展示用模板正文留在页面，不在提交前再次查询。群发核对复用已选模板及 CSV 列定义，文件、列定义或引流正文改变时重新检查；上传账号绑定、文件完整性和一次回读保留。引流录入按接口受理结果展示，不再等待逐条资源 ID 回读。
